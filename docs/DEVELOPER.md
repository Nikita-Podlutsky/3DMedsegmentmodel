# Глубокий технический разбор архитектуры (Developer Guide)

В этом документе подробно описаны инженерные решения, математика лоссов и особенности реализации двухэтапной 3D-сегментации.

## 1. Концепция Coarse-to-Fine (Грубый-к-Точному)

Главная проблема при сегментации 3D-данных (МРТ) — высокая ресурсоемкость. Сканы объемом, например, $512 \times 512 \times 256$ вокселей физически невозможно пропустить через глубокую 3D-сеть на стандартных GPU из-за нехватки видеопамяти. Нарезка на случайные куски (патчи) решает проблему с памятью, но лишает сеть понимания глобального контекста (она "не понимает", где находится патч — в лобной доле или затылочной).

Для решения этой проблемы мы используем двухэтапную архитектуру:

```
                  ┌──────────────────────┐
                  │ Полное МРТ (Raw 3D)  │
                  └──────────┬───────────┘
                             │
              [Даунсемплинг до 128x128x128]
                             │
                             ▼
                 ┌───────────────────────┐
                 │  CoarseUNet_Medium    │ (Грубая сеть)
                 └──────────┬────────────┘
                             │
                   [Карта вероятностей]
                             │
                             ▼
  ┌─────────────────────────────────────────────────────┐
  │                   Проход по патчам                  │
  │                                                     │
  │  ┌──────────────┐ ┌──────────────┐ ┌─────────────┐  │
  │  │ Патч снимка  │ │ Патч грубой  │ │ Координаты  │  │
  │  │  (высокое    │ │    маски     │ │  вокселей   │  │
  │  │ разрешение)  │ │ (ориентир)   │ │  [-1, 1]    │  │
  │  └──────┬───────┘ └──────┬───────┘ └──────┬──────┘  │
  │         │                │                │         │
  │         └────────────────┼────────────────┘         │
  │                          │                          │
  │                          ▼                          │
  │             ┌─────────────────────────┐             │
  │             │ MultiTask_FineUNet_MoE  │             │ (Точная сеть)
  │             └────────────┬────────────┘             │
  │                          │                          │
  └──────────────────────────┼──────────────────────────┘
                             │
                 [Финальная точная маска]
```

1.  **Coarse Stage (Грубый этап):** Полный 3D-скан сжимается до фиксированного небольшого размера (например, $128 \times 128 \times 128$). Сеть `CoarseUNet_Medium` (легкий 3D U-Net) делает быстрый проход и выдает приближенную маску. Результат апсемплится обратно в исходный размер.
2.  **Fine Stage (Точный этап):** Снимок нарезается на перекрывающиеся патчи (например, $64 \times 64 \times 64$). На вход точной сети подается объединенный по каналам тензор:
    *   **Канал 0:** Оригинальный патч МРТ (высокое разрешение, локальные детали).
    *   **Канал 1:** Соответствующий патч грубой маски (дает анатомический контекст — где мы находимся относительно всего органа).
    *   **Каналы 2–4 (опционально):** Трехмерная координатная сетка вокселей, нормализованная в диапазоне $[-1, 1]$. Это дает сети строгое понимание абсолютных геометрических границ.

## 2. Устройство точной сети (`src/models.py`)

Точная модель `MultiTask_FineUNet_MoE` — это глубокий 3D U-Net с двумя ключевыми модификациями: ** Mixture of Experts (MoE)** и **Multi-Task обучением**.

### Смесь экспертов (MoE) под капотом
Вместо классических сверточных слоев мы используем слои `MoELayer` [1]. Каждый такой слой содержит:
*   **Набор экспертов** — $N$ независимых параллельных блоков `ResBlock3D`.
*   **Гейтинговую сеть** (`gating_network`) — легкий блок из адаптивного пулинга и полносвязного слоя.

Математически проход через MoE-слой выглядит так:

$$y = \sum_{i=1}^{N} G(x)_i \cdot E_i(x)$$

Где $G(x)_i$ — вес (вероятность), назначенный $i$-му эксперту гейтинговой сетью (через Softmax), а $E_i(x)$ — выход этого эксперта. Это позволяет сети динамически переключаться между разными "экспертами" в зависимости от того, обрабатывает ли она сейчас границу ткани, однородную внутреннюю область или фоновый шум.

### Многозадачность (Multi-Task Learning)
Для лучшей регуляризации в бутылочное горлышко (bottleneck) сети встроен классификатор модальностей. 
*   **Задача 1 (Сегментация):** Основная декодерная ветка сети собирает фичи обратно в маску.
*   **Задача 2 (Классификация):** Bottleneck-фичи пропускаются через адаптивный пулинг и полносвязный слой для предсказания модальности МРТ (T1, T2, FLAIR и т.д.).
Это заставляет энкодер сети извлекать универсальные физические свойства тканей, а не просто "зубрить" геометрию конкретного набора данных.

## 3. Консистентность данных и препроцессинг (`src/data_units.py`)

### Проблема зеркальности осей
При обработке медицинских снимков (особенно в формате NIfTI `.nii.gz`) легко запутаться в порядке осей: `(Width, Height, Depth)` или `(Depth, Width, Height)`. 
Если при подготовке данных оси перепутаны, координатные карты $[-1, 1]$ будут накладываться некорректно (модель будет путать лево-право или верх-низ).

Мы стандартизировали все данные под жесткий формат **`(C, D, H, W)`** (Channel, Depth, Height, Width):
```python
# Порядок осей строго приводится к (C, D, H, W) перед подачей в сеть
image_tensor = torch.from_numpy(image_volume.transpose(3, 0, 1, 2)).float()
```
Это гарантирует, что координатные карты, генерируемые на лету через `torch.linspace`, идеально совпадают с геометрией снимка.

## 4. Логика отказоустойчивого инференса (`src/inference.py`)

Для инференса используется обертка `UnifiedPatchedModel`, которая решает проблему краевых эффектов и нестандартных размеров снимков.

### Проблема анизотропных малых сканов
Стандартный алгоритм скользящего окна падает, если размер входного МРТ по какой-то оси меньше размера патча (например, патч $64 \times 64 \times 64$, а скан пришел $128 \times 128 \times 40$).
Мы решили эту проблему через **динамический анизотропный падинг**:

```python
# Если размер меньше патча, рассчитываем недостающий падинг
pad_d = (sd - (D - pd) % sd) % sd if D > pd else (pd - D)
pad_h = (sh - (H - ph) % sh) % sh if H > ph else (ph - H)
pad_w = (sw - (W - pw) % sw) % sw if W > pw else (pw - W)
```
После работы сети по всей забитой нулями площади, результат аккуратно обрезается обратно до исходных размеров `(D, H, W)`.

## 5. Численная стабильность обучения (`src/training_pipeline.py`)

### Стабильный комбинированный лосс
В качестве целевой функции используется комбинация Dice Loss и Binary Cross Entropy (BCE):

```python
bce_loss = F.binary_cross_entropy_with_logits(inputs, targets, reduction='mean')
```
Использование `binary_cross_entropy_with_logits` критически важно. В отличие от стандартного `F.binary_cross_entropy(torch.sigmoid(x))`, функция с логитами вычисляется математически сгруппировано, что предотвращает появление экстремальных значений $\log(0)$ и защищает обучение от появления `NaN` в градиентах при высокой уверенности сети.

### Безопасная загрузка состояния
Чтобы избежать падения при возобновлении обучения с чекпоинта, все компоненты инициализируются в строгом порядке. Оптимизатор и шедулер инициализируются **до** вызова `load_state_dict`, а переменная `self.start_epoch` корректно считывается из сохраненного состояния, предотвращая затирание старых логов обучения:

```python
self.start_epoch = save_point.get('epoch', 0) + 1
```
