# Глубокий технический разбор архитектуры (Developer Guide)

В этом документе подробно описаны инженерные решения, математика лоссов и особенности реализации двухэтапной 3D-сегментации.

---

## 1. Концепция Coarse-to-Fine (Грубый-к-Точному)

Главная проблема при сегментации 3D-данных (МРТ) — высокая ресурсоемкость. Сканы физически невозможно пропустить через глубокую 3D-сеть на стандартных GPU из-за нехватки видеопамяти. Нарезка на случайные куски (патчи) решает проблему с памятью, но лишает сеть понимания глобального контекста.

Для решения этой проблемы мы используем двухэтапную архитектуру:

```
                  ┌──────────────────────┐
                  │ Полное МРТ (Raw 3D)  │
                  └──────────┬───────────┘
                             │
              [Даунсемплинг до 64x64x64/128]
                             │
                             ▼
                 ┌───────────────────────┐
                 │      CoarseUNet       │ (Грубая многозадачная сеть)
                 └──────┬─────────┬──────┘
                        │         │
        [Логиты модальности]      [Карта вероятностей]
             (класса)             (низкое разрешение)
                        │                 │
                        │            [Апсемплинг]
                        │                 │
                        ▼                 ▼
  ┌─────────────────────────────────────────────────────┐
  │                   Проход по патчам                  │
  │                                                     │
  │  ┌──────────────┐ ┌──────────────┐ ┌─────────────┐  │
  │  │ Патч снимка  │ │ Патч грубой  │ │ Координаты  │  │
  │  │  (высокое    │ │    маски     │ │  вокселей   │  │
  │  │ разрешение)  │ │ (ориентир)   │ │  [-1, 1]    │  │
  │  └──────┬───────┘ └──────┬───────┘ └──────┬──────┘  │
  │         │                │                │         │
  │         └────────────────┼────────────────┘         │
  │                          │                          │
  │                          ▼                          │
  │                     ┌──────────┐                    │
  │                     │ FineUNet │                    │ (Точная сеть)
  │                     └────┬─────┘                    │
  │                          │                          │
  └──────────────────────────┼──────────────────────────┘
                             │
                 [Финальная точная маска]
```

1.  **Coarse Stage (Грубый этап):** Полный 3D-скан сжимается до фиксированного небольшого размера (например, $64 \times 64 \times 64$). Сеть `CoarseUNet` делает быстрый проход и решает сразу две задачи: строит грубую карту вероятностей объекта и глобально классифицирует модальность всего снимка по его bottleneck-признакам. Маска апсемплится обратно в исходный размер.
2.  **Fine Stage (Точный этап):** Снимок нарезается на перекрывающиеся патчи. На вход точной сети `FineUNet` подается объединенный по каналам тензор:
    *   **Канал 0:** Оригинальный патч МРТ (высокое разрешение, локальные детали).
    *   **Канал 1:** Соответствующий патч грубой маски (анатомический контекст).
    *   **Каналы 2–4 (опционально):** Трехмерная координатная сетка вокселей, нормализованная в диапазоне $[-1, 1]$ (понимание геометрических границ).
    *   **Логиты класса:** Вектор `cls_logits`, полученный от Coarse-модели, подается напрямую во все MoE-блоки для управления экспертами.

## 2. Устройство точной сети (`src/models.py`)

Точная модель `FineUNet` — это глубокий 3D U-Net, использующий блоки смеси экспертов **MoEBlock3D** и концепцию **управляемой маршрутизации**.

### Контролируемая смесь экспертов (MoE)
В классических MoE-архитектурах гейтинг работает в режиме unsupervised обучения, что часто приводит к "коллапсу экспертов" (когда один эксперт обрабатывает 95% данных, а остальные бездействуют). Мы решили эту проблему, привязав маршрутизацию экспертов к глобальной классификации модальности [1.2.4]:

*   Каждый слой `MoEBlock3D` содержит набор экспертов на базе `ResidualBlock3D`.
*   Вместо локального пулинга и гейтинга внутри слоя работает легкий линейный адаптер `route_adapter`.
*   Он принимает на вход готовый вектор логитов модальностей `cls_logits` от `CoarseUNet` и преобразует его в веса активации экспертов.

Математически проход через MoE-блок выглядит так:

$$y = \sum_{i=1}^{N} A(c)_i \cdot E_i(x)$$

Где $c$ — глобальные логиты классификации от грубого этапа, $A(c)_i$ — коэффициент важности для $i$-го эксперта, полученный через линейный адаптер и Softmax, а $E_i(x)$ — выход $i$-го эксперта (`ResidualBlock3D`). Это обеспечивает строго контролируемую специализацию: эксперты учатся работать с конкретными физическими модальностями тканей.

## 3. Консистентность данных и препроцессинг (`src/data_units.py`)

### Проблема зеркальности осей
При обработке медицинских снимков (особенно в формате NIfTI `.nii.gz`) легко запутаться в порядке осей: `(Width, Height, Depth)` или `(Depth, Width, Height)`. 
Если при подготовке данных оси перепутаны, координатные карты $[-1, 1]$ будут накладываться некорректно (модель будет путать лево-право или верх-низ).

Мы стандартизировали все данные под жесткий формат **`(C, D, H, W)`** (Channel, Depth, Height, Width):
```python
# Порядок осей строго приводится к (C, D, H, W) перед подачей в сеть
image_tensor = torch.from_numpy(image_volume.transpose(3, 0, 1, 2)).float()
```
Это гарантирует, что координатные карты, генерируемые на лету через `torch.linspace`, идеально совпадают с геометрией снимка.

## 4. Логика инференса скользящим окном (`src/inference.py`)

Для инференса используется обертка `UnifiedPatchedModel`, которая решает проблему краевых эффектов и нестандартных размеров снимков.

### Проблема анизотропных малых сканов
Стандартный алгоритм скользящего окна падает, если размер входного МРТ по какой-то оси меньше размера патча (например, патч $32 \times 32 \times 32$, а скан пришел $128 \times 128 \times 16$).
Мы решили эту проблему через **динамический анизотропный падинг**:

```python
# Если размер меньше патча, рассчитываем недостающий падинг
pad_d = (sd - (D - pd) % sd) % sd if D > pd else (pd - D)
pad_h = (sh - (H - ph) % sh) % sh if H > ph else (ph - H)
pad_w = (sw - (W - pw) % sw) % sw if W > pw else (pw - W)
```
После работы сети по всей забитой нулями площади, результат аккуратно обрезается обратно до исходных размеров `(D, H, W)`.

## 5. Численная стабильность обучения (`src/training_pipeline.py`)

### Стабильный комбинированный лосс
В качестве целевой функции используется комбинация Dice Loss и Binary Cross Entropy (BCE):

```python
bce_loss = F.binary_cross_entropy_with_logits(inputs, targets, reduction='mean')
```
Использование `binary_cross_entropy_with_logits` критически важно. В отличие от стандартного `F.binary_cross_entropy(torch.sigmoid(x))`, функция с логитами вычисляется математически сгруппировано, что предотвращает появление экстремальных значений $\log(0)$ и защищает обучение от появления `NaN` в градиентах при высокой уверенности сети.

### Безопасная загрузка состояния
Чтобы избежать падения при возобновлении обучения с чекпоинта, все компоненты инициализируются в строгом порядке. Оптимизатор и шедулер инициализируются **до** вызова `load_state_dict`, а переменная `self.start_epoch` корректно считывается из сохраненного состояния, предотвращая затирание старых логов обучения:

```python
self.start_epoch = save_point.get('epoch', 0) + 1
```
